## 1. 목표
클로드를 이용해서 여러 "AI 직원"으로 이루어진 팀을 만들고, 새 쇼핑몰을 어떻게 운영할지 계획을 세우는 게 목표예요. 하고 싶은 건 3가지예요:
- 고객이 검색했을 때 우리 상품이 잘 보이고, AI가 알아서 좋은 상품을 추천해주게 하기 (SEO = 검색엔진최적화)
- 잘 팔릴 것 같은 상품을 미리 찾아내기
- SNS 홍보(인스타그램, 틱톡 등)가 자동으로 돌아가게 하기
이런 AI 직원들을 만들 때 제일 중요한 원칙은 **"나중에 언제든 쉽게 고쳐 쓸 수 있게" 만드는 것**이에요. (전문 용어로 "하네스 엔지니어링"이라고 하는데, 쉽게 말하면 "AI에게 줄 설명서 + 실제로 일할 도구를 잘 조합해서 팀을 꾸리는 기술"이라고 생각하면 돼요.)
## 2. 조직 구조
실제 회사의 조직도와 똑같이 생각하면 쉬워요. "팀장 AI" 밑에 각자 맡은 일이 다른 "담당 AI" 5명을 두는 구조예요. AI마다 실제로 관리하는 사람(팀원)이 한 명씩 붙어있어요 — 배정 이유는 9번 섹션에 자세히 있어요. 또, 다른 5개 AI가 만드는 결과물(문서·메시지·시트 등)이 서로 따로 놀지 않도록 검수하는 "포맷·일관성 관리 AI"가 별도로 있어요 (19번 섹션 참고).
```javascript
[팀장 AI = 운영자] (= LLM 최고 모델 자체, 팀원들이 필요시 설정·조작) — 전체 방향을 정하고, 아래 AI들에게 일을 나눠줌
   ├─ 검색 잘되게 하는 AI (SEO) — 담당: 팀원 B
   ├─ 인기 상품 찾는 AI — 담당: 팀원 B
   ├─ 상품 추천해주는 AI — 담당: 팀원 A
   ├─ SNS 홍보 자동화 AI — 담당: 팀원 A
   ├─ 성과 확인하는 AI — 담당: 팀원 A
   └─ 포맷·일관성 관리 AI (위 5개 전체의 출력물을 검수) — 담당: 팀원 B
```
## 3. 각 AI가 하는 일

| AI 이름 | 하는 일 | 필요한 것 |
|---|---|---|
| 검색최적화(SEO) AI | 사람들이 어떤 단어로 검색하는지 찾고, 경쟁사는 상품을 어떻게 써놨는지 분석해서, 우리 상품 페이지가 검색에 잘 걸리게 고침 + ChatGPT 같은 AI 쇼핑 에이전트가 우리 상품을 정확히 읽고 추천하도록 구조화 데이터(스키마마크업)도 관리 (사람 대상 SEO + AI 에이전트 대상 GEO를 함께 담당) | 웹검색 기능, 상품 구조화 데이터(JSON-LD) 관리 |
| 인기상품 발굴 AI | 네이버·구글에서 요즘 뭐가 뜨는지, SNS에서 뭐가 많이 언급되는지 찾아서 팔릴 만한 상품을 미리 알려줌 | 웹검색, 트렌드 정보 연결 |
| 상품 추천 AI | 고객이 뭘 검색했는지, 뭘 봤는지 보고 어울리는 다른 상품을 같이 추천해줌 | 상품 목록 데이터 |
| SNS 홍보 AI | 홍보 문구를 쓰고, 이미지·짧은 영상 초안을 만들고, 정해진 시간에 자동으로 올림 | Canva(이미지 도구), SNS 계정 연결 |
| 성과 분석 AI | 얼마나 팔렸는지 모아서 보여주고, 다음엔 뭘 하면 좋을지 제안 | 데이터 정리 도구 |
| 포맷·일관성 관리 AI | 규칙·변수·엑셀 컬럼·문서 양식·메시지·출력 포맷을 한곳에서 관리하고, 다른 5개 AI가 무언가를 밖으로 내보낼 때마다 기존 규칙과 맞는지 검수하고 "통일성 점수"를 매김 | 체크리스트, 17번 섹션의 합격 기준 개념 재사용 |

### SEO의 새 과제 — "사람에게 팔기" + "AI 에이전트에게 팔기" (GEO)
**사용자 제안(2026-09-25)**: 이제는 손님이 직접 검색해서 사는 것 말고도, 손님을 대신해 움직이는 "AI 쇼핑 에이전트"(예: ChatGPT)가 상품을 찾고 대신 골라주는 경우가 늘고 있어요. 이 경우 우리 SEO AI가 설득해야 할 대상은 사람이 아니라 또 다른 AI예요 — 말 그대로 **"에이전트가 에이전트를 설득"**해야 하는 구조죠.
**공식 확인(2026-09-25, [developers.openai.com/commerce](http://developers.openai.com/commerce) 기준)**: ChatGPT 안에서 우리 상품이 검색·추천되게 하려면, 사람이 읽는 상품 설명과는 별도로 AI가 정확히 읽을 수 있는 "상품 데이터 피드"를 제공해야 해요. 필수 항목은 이래요:

| 항목 | 필수여부 | 설명 |
|---|---|---|
| item_id | 필수 | 상품(옵션)별 고유 ID |
| title | 필수 | 상품명 (최대 150자) |
| description | 필수 | 사실 위주 상품 설명 (최대 5,000자) |
| url / brand / seller_name / image_url | 필수 | 상품페이지 링크, 브랜드명, 판매자명, 대표 이미지 |
| availability | 필수 | 재고 상태 (in_stock 등) |
| price | 필수 | 가격 + 통화코드 (예: "79.99 USD") |
| is_eligible_checkout, seller_privacy_policy, seller_tos | 결제 지원 시 추가 필수 | ChatGPT 안에서 바로 결제까지 받으려면 추가로 필요 |

**⚠️ 최신 확인(2026-09-25)**: "Instant Checkout"(ChatGPT 안에서 바로 결제) 기능 자체는 최근 중단됐다는 보도가 있지만, 그 밑바탕인 "에이전트형 상거래 프로토콜(ACP)"과 이 상품 피드 규격은 계속 유지되고 있어요 — 결제 기능이 바뀌어도 "AI가 우리 상품 데이터를 정확히 읽을 수 있게 만드는 것" 자체는 계속 중요해요.
**미확인**: 카페24가 이 피드 규격(ACP)을 지원하는지, 비슷한 자체 기능이 있는지는 아직 확인 안 됨 — 지금은 Shopify·Etsy 위주로 연동돼 있어요. 다음 주 카페24 개발자센터에서 재확인 (13번 섹션과 연결).
**"에이전트를 설득"하는 3가지 포인트**: (1) 가격·재고 정보가 상품페이지·피드·구조화데이터 세 곳에서 전부 일치해야 함 (다르면 AI가 신뢰하지 않음) (2) 리뷰·평점 같은 신뢰 신호가 있어야 함 (3) 데이터가 최신이어야 함(15분~마다 갱신 권장). SEO AI가 사람 눈에 예쁜 문구뿐 아니라, 이 3가지를 관리하는 역할까지 함께 맡아요.
*(출처: [OpenAI Agentic Commerce 공식 문서](https://developers.openai.com/commerce/product-feeds/spec), [OpenAI 공식 발표](https://openai.com/index/buy-it-in-chatgpt/))*
### 인기상품 발굴 AI — 네이버·유튜브·인스타그램, 국내 기준 실현 가능한 방법 (2026-09-25 확인)
**결론부터**: 유튜브는 공식 API로 거의 다 됨, 네이버는 부분적으로만 됨(카테고리 단위), 인스타그램은 공식 API로는 "발견"이 안 되고 사람이 직접 봐야 해요.

| 플랫폼 | 공식 API로 되는 것 | 안 되는 것 | 비용 | 확인 상태 |
|---|---|---|---|---|
| 유튜브 | `videos.list?chart=mostPopular&regionCode=KR` 호출 한 번으로 국내 인기 급상승 영상 목록을 통째로 가져옴. 음악·게임 등 카테고리로 좁히는 것도 가능 | 딱히 없음 — 사실상 다 됨 | 무료 (하루 쿼터 1만 유닛, 이 호출은 1유닛이라 매우 여유로움) | 높음 (공식 문서 직접 확인) |
| 네이버 | 데이터랩 쇼핑인사이트 API로 "카테고리별 인기 추이"(상대 지수)는 확인 가능 | "지금 뜨는 개별 검색어 순위"(옛 급상승 검색어)는 2021년에 서비스 자체가 없어져서 공식 API로 못 함 | 무료 | 중간 (2차 소스 기반 — 공식 문서 직접 열람은 실패해서 재확인 필요) |
| 인스타그램 | 이미 정해둔 특정 해시태그 1개의 최근 공개 게시물 조회 (주당 30개 해시태그 한도, 비즈니스 계정 연결 필요) | "요즘 뜨는 해시태그가 뭔지" 찾아내는 기능 자체가 공식 API에 아예 없음 | 무료(제한적) / 유료 소셜리스닝 툴은 별도 비용 | 높음 (공식 문서 기반) |

**그래서 실현 가능한 구조는 이래요**:
1. **발견(찾기)은 유튜브 중심** — `chart=mostPopular&regionCode=KR`로 국내 인기 영상을 매일/매주 가져와서, 제목·설명에서 상품·브랜드 키워드를 뽑아냄
2. **검증은 네이버** — 유튜브에서 뽑은 후보 키워드를 네이버 데이터랩 쇼핑인사이트(카테고리 트렌드)와 이미 만든 네이버쇼핑 검색 API(16번 섹션)에 넣어서, 실제로 얼마나 검색·판매되는지 교차 확인
3. **인스타그램은 사람이 보조** — 공식 API로 "발견"이 안 되니까, 팀원이 인스타 탐색탭이나 경쟁사 계정을 가끔 훑어보고 눈에 띄는 걸 단톡방에 공유하면 클로드가 정리 (10번 섹션의 옵시디언 흐름 재사용). 후보가 나오면 그 해시태그 하나만 공식 Hashtag Search API로 "실제로 게시물이 많은지" 사후 확인하는 보조 용도로만 씀
**미검증**: 네이버 데이터랩 API의 정확한 일일 호출 한도, 유튜브 API 쿼터를 카테고리별로 얼마나 쓰게 될지는 실제 신청 후 재확인 필요.
*(출처: YouTube Data API 공식 문서, Instagram Graph API 공식 문서, 네이버 개발자센터 — 2차 소스 교차 확인)*
## 4. "AI 팀 꾸리는 방법" 쉽게 이해하기
AI 팀을 만들 때 필요한 건 딱 3가지예요:
- **설명서(Skill)**: "이 일은 이런 순서로, 이런 기준으로 판단해"라고 AI에게 알려주는 지침서
- **도구(Tool)**: AI가 실제로 검색하거나, 자료를 찾거나, SNS에 글을 올릴 때 쓰는 손발
- **작업 환경**: 이 설명서와 도구를 합쳐서 실제로 돌아가게 해주는 곳 (지금 쓰고 있는 클로드 코드가 바로 이거예요)
그러니까 우리가 만들 건 대부분 복잡한 "코드"가 아니라, 그냥 **AI에게 주는 설명서**예요. 파이썬 코드는 정말 자동화가 필요한 부분에만 최소한으로 쓰면 돼요.
### 에이전트를 따로 나눌까, 설명서(스킬)만 나눌까? (2026-09-25 확인)
**결론부터**: 지금 규모(팀원 2명, 신규 쇼핑몰)에서는 **설명서(스킬)만 나누는 쪽이 압도적으로 편해요.** 5개 담당 AI = 5개의 설명서 파일. 팀장 AI 하나가 상황에 맞는 설명서를 그때그때 꺼내 쓰는 구조예요.

| 구분 | 설명서(스킬)만 나누기 | 에이전트를 따로 나누기 |
|---|---|---|
| 관리 난이도 | 쉬움 — 파일 하나만 고치면 그 AI 역할이 바뀜 | 어려움 — 에이전트마다 설정을 따로 챙겨야 함 |
| 대화 내용 공유 | 한 대화 안에서 공유됨 (SEO 하다 찾은 키워드를 바로 다음 작업에 이어 씀) | 서로 분리됨 (장점이자 단점) |
| 동시에 여러 개 처리 | 못 함 (하나씩 순서대로) | 가능 (여러 개를 한 번에 병렬로) |
| 팀원이 다루기 | 쉬움 — 그냥 설명서 문서 수정 | 어려움 — 구조를 더 알아야 함 |
| 지금 우리한테 맞나 | ✅ 지금은 이걸로 충분 | 나중에 필요해지면 |

**에이전트를 따로 나누는 게 필요해지는 때는 딱 2가지예요**: (1) 진짜 여러 개를 동시에 처리해야 할 때 (예: 상품 50개의 SEO 문구를 한 번에 병렬로 만들기) (2) 한 작업이 너무 방대해서 대화 내용이 꽉 찰 때 (예: 유튜브 영상 200개를 하나하나 다 읽고 분석하기 — 이럴 땐 그 방대한 내용을 별도 에이전트에 맡겨서 메인 대화가 지저분해지지 않게 함). 지금은 둘 다 해당 안 되니, 5번 섹션 원칙(하나씩 따로 만들기)대로 설명서만 나누는 걸로 시작하고, 특정 역할이 실제로 위 2가지 상황에 부딪히면 그 역할만 에이전트로 승격하면 돼요.
## 5. 나중에 쉽게 고쳐 쓰기 위한 원칙
1. **하나씩 따로 만들기** — AI 하나당 설명서 하나. SNS 홍보 방식을 바꿔도 검색최적화 AI는 안 건드려도 돼요.
2. **바뀐 기록 남기기(버전 관리)** — 설명서 파일을 계속 저장해두면, 언제 뭘 바꿨는지 나중에 확인하고 되돌리기 쉬워요.
3. **정보를 주고받는 형식을 미리 정하기** — "상품 정보"에 어떤 항목(이름/가격/카테고리 등)이 들어갈지 처음에 정해두면, AI 하나를 바꿔도 나머지는 그대로 잘 연결돼요.
4. **결과를 보고 계속 개선하기** — 주기적으로 성과를 확인해서, 그 결과를 보고 어떤 AI를 고칠지 정해요.
5. **"왜 이렇게 만들었는지" 적어두기** — 몇 달 뒤에 다시 봤을 때 헷갈리지 않으려면, 이유를 같이 남겨둬요.
6. **항상 비용과 효율을 같이 비교하기** — 새로운 도구나 요금제를 쓸지 말지 정할 때는, "제일 싼 방법"과 "제일 효율적인 방법"을 나란히 보여주고 팀이 직접 고르게 해요. (8번에서 처음 이렇게 해봤어요)
## 6. 시작 순서

- [ ] 2~3주차: "상품 추천 AI" 만들어서 상세페이지에 적용
- [ ] 4주차: SNS 홍보 자동화 시작 (글쓰기 → 자동 게시)
- [ ] 5주차~: 성과를 확인하면서 하나씩 고쳐 나가기
## 7. 이미 있는 도구 쓰기 vs 직접 만들기
- **그냥 있는 거 쓰면 되는 것**: 계획 정리는 Notion, 이미지는 Canva, 파일 저장은 Google Drive — 이미 연결돼 있어서 바로 쓰면 돼요.
- **우리가 직접 만들어야 하는 것**: "우리 쇼핑몰만의 기준"이 필요한 부분 — 어떤 상품이 좋은 상품인지 판단하는 기준, 우리 브랜드 말투에 맞는 SNS 문구 스타일 같은 것들. 이런 건 범용 도구가 없어서 직접 설명서(Skill)를 만들어야 해요.
## 8. 팀 소통 방법 — 얼마나 쓸지 vs 얼마나 편할지
팀원 2명 다 Claude Pro를 쓰고 있고, 컴퓨터 쪽은 잘 모른다는 걸 감안해서 3가지 방법을 비교했어요. 이 표를 보고 팀이 직접 고르면 돼요.

|   | A. 지금 이대로 (제일 쌈) | B. 중간 단계 | C. 다 같이 실시간 대화 (편함, 대신 비쌈) |
|---|---|---|---|
| 방법 | Pro 그대로 쓰고, 카카오톡 같은 무료 단톡방에 결과만 공유 | 2명 다 Claude "Team" 요금제로 바꾸기만 함 | Team 요금제 + Slack에 "Claude Tag" 기능을 켜서, 여러 명이 한 채팅방에서 클로드를 같이 부르는 방식 |
| 한 달 비용(2명 기준) | 지금이랑 같음 (1인당 약 $20) | 비슷함 (1인당 약 $20~25) | 위 비용 + 최소 한 달 $500 정도 추가 예산 필요 (실제 쓴 만큼만 나감) |
| 여러 명이 동시에 클로드랑 대화 | ❌ 안 됨 (각자 따로 씀) | ❌ 안 됨 | ✅ 됨 |
| 옵시디언 자료 → 구글시트 자동 정리 | ❌ 사람이 손으로 옮겨야 함 | ❌ | ✅ 자동으로 가능 |
| 언제 필요한가 | 아직 매출도 없고 방식을 테스트하는 지금 | 딱히 이점이 없어서 우선순위 낮음 | 리서치 양이 많아져서 자동화가 실제로 시간을 아껴줄 때 |

**결론**: 지금은 A(그냥 무료로 시작)로 하고, 나중에 자동화가 확실히 시간을 아껴준다는 확신이 들면 C로 넘어가는 걸 추천해요. B는 돈은 비슷하게 드는데 실제로 얻는 게 별로 없어서 우선순위가 낮아요.
**알아두면 좋은 사실 (2026-09-24 기준 확인)**:
- "Claude Tag"(여러 명이 같이 대화하는 기능)는 Pro나 Max 요금제로는 못 쓰고, Team 이상 요금제에서만 쓸 수 있어요.
- Team 요금제는 최소 2명부터 가입할 수 있어요.
- Claude Tag를 켜면 요금제 비용과 별도로 실제 쓴 만큼 추가 비용이 나가요. 관리자가 한 달에 최대 얼마까지 쓸지 미리 정해둬야 해요 (제일 작은 선택지가 한 달 $500).
- Team 가입 시 주던 $2,500 할인 크레딧은 2026년 9월 1일에 끝나서, 지금은 못 받을 가능성이 커요 (가입 화면에서 재확인 필요).
*(출처: [Claude Tag 설정 공식 문서](https://claude.com/docs/claude-tag/admins/setup-overview), [Claude 요금제](https://claude.com/pricing))*
### A안 하는 법 (더 쉽게)
- 팀원이 각자 자기 Pro 계정으로 조사·분석
- 결과를 카톡방 같은 데 붙여넣어서 공유
- 구글시트 정리는 자동으로 안 되니까 사람이 직접 옮겨 적어야 함
### C안 켜는 법 (Slack 관리자가 진행, 5단계)
1. `claude.ai/admin-settings/claude-tag` 들어가기 (Team 요금제 관리자만 가능)

3. 받은 코드를 설정 페이지에 입력

## 9. 역할 나누기 (2명)
팀원 2명은 50대 남성이고, 각자 강점이 뚜렷해요 — **A는 영업 경험 + 꼼꼼함**, **B는 악기 개발(제품 개발) 경험 + 파이썬을 조금 다룰 수 있음**. 이 정보를 반영해서 역할을 다시 나눴어요.
**참고 0 (용어 구분)**: "운영자" = 사람이 아니라 팀장 AI(LLM 최고 모델 자체)예요. 실제 사람은 팀원 A, 팀원 B 둘뿐이고요. 계정·요금제 설정같이 사람만 할 수 있는 일은, 그 순간에 클로드를 직접 다루는 팀원이 처리하면 돼요.

| 이름 | 담당 AI | 실제로 하는 일 | 왜 이 역할이 맞나 |
|---|---|---|---|
| 팀원 A (영업경험, 꼼꼼함) | 상품 추천·큐레이션 AI + SNS 홍보 AI + 성과 분석 AI | 고객이 원할 만한 상품 조합을 최종 확인, 홍보 문구·이미지가 설득력 있고 오류 없는지 꼼꼼하게 검수한 뒤 게시 승인, 매출 데이터 보고 확인 후 다음 전략 결정 | 영업 경험 → 고객이 뭘 원하는지, 뭐가 설득력 있는 제안인지 보는 감각이 있고 매출 숫자도 같은 관점으로 볼 수 있음 / 꼼꼼함 → 문구나 추천 결과의 사소한 오류까지 잘 잡아냄 |
| 팀원 B (악기개발 경험, 파이썬 조금) | 인기상품 발굴 AI + 검색최적화(SEO) AI + 포맷·일관성 관리 AI | AI가 찾은 트렌드 후보를 "실제로 좋은 제품인지" 제품개발자 시각으로 검토, SEO 결과 확인, 다른 AI들이 내보내려는 결과물이 기존 규칙·양식과 맞는지 검수, 필요하면 간단한 자동화 스크립트도 해보기 | 직접 제품(악기)을 개발해본 경험 → 좋은 상품을 보는 안목 / 파이썬을 조금 알아서 테스트 결과를 보고 더 정확히 판단할 수 있음 / 꼼꼼함과 별개로, 형식·규칙이 잘 지켜지는지 보는 성향이 포맷·일관성 관리에도 잘 맞음 |

**참고 1**: 옵시디언 웹클리퍼로 자료 모으는 건(10번 섹션) 두 분 다 공통으로 하면 돼요. 담당 AI가 다를 뿐, 눈에 띄는 상품·트렌드 자료는 누구든 발견하면 모아서 공유하는 게 좋아요.
**참고 2**: 나중에 반복 작업을 자동화하는 파이썬 스크립트가 필요해지면(11번 섹션의 API 직접 호출 등), 구현 자체는 클로드(AI)가 하고 팀원 B는 실제로 잘 돌아가는지 테스트하는 역할을 맡으면 돼요. 코드를 직접 짜지 않아도 괜찮아요.
## 10. 자료 모으는 방법 (옵시디언 → 메신저 → 구글시트)
팀원들이 각자 조사한 자료가 여기저기 흩어지지 않게, 한곳에 모아서 클로드가 정리해주는 흐름이에요. **8번의 C안(Team + Claude Tag)을 골랐을 때만 완전 자동으로 돌아가요.**
### 순서
1. 팀원이 관심 있는 상품·트렌드 페이지를 "Obsidian Web Clipper"(브라우저에 설치하는 확장 프로그램, 클릭 한 번으로 페이지 내용을 저장해줌)로 저장
2. 저장한 내용(제목·링크·요약)을 Slack 리서치 채팅방에 붙여넣기
3. 클로드가 그 내용을 읽고 정해진 항목대로 정리
4. 구글시트 "리서치 로그"에 한 줄로 자동 추가
### 시트에 들어갈 항목
날짜 / 누가 모았는지 / 원본 링크 / 종류(트렌드·경쟁상품 등) / 상품·키워드 이름 / 짧은 요약 / 어느 AI가 쓸 자료인지 / 중요도 / 진행 상태
### ⚠️ 확인해야 할 점
Slack에 붙여넣기만 하면 바로 구글시트에 추가되려면, Claude Tag 설정할 때 "Google Sheets" 연동까지 켜져 있어야 해요. 안 되면 Zapier 같은 다른 자동화 도구를 쓰거나, 클로드는 내용 정리만 하고 시트에 옮기는 건 사람이 해야 해요.
**지금(A안 쓰는 동안)은**: 팀원이 옵시디언에서 모은 내용을 그냥 단톡방에 공유하면, 팀원 중 한 명이 주기적으로 모아서 정리한 다음 구글시트에 직접 옮겨 적을게요.
### 팁
팀원들이 옵시디언에서 저장할 때 항상 같은 형식(제목/링크/요약)으로 저장하면, 클로드가 매번 헷갈리지 않고 정리하기 쉬워져요.
## 11. 팀장 AI(오케스트레이터)는 어떤 모델을 쓸까
팀장 AI는 제일 중요한 판단을 하는 역할이니까 "제일 똑똑한 AI 모델"을 쓰는 게 맞아요. 다만 그걸 어떻게 쓰느냐(구독 vs API로 직접 연결)에 따라 비용이랑 난이도가 완전히 달라져요.

|   | 구독으로 쓰기 (지금 방식) | API로 직접 연결하기 |
|---|---|---|
| 돈 내는 방식 | 매달 정해진 금액 (1인당 약 $20) | 쓴 만큼 냄 (AI가 얼마나 읽고 썼는지에 따라) |
| 모델 고르는 자유도 | 정해진 몇 개 중에서 고름 | 최신 모델 아무거나 자유롭게 고를 수 있음 |
| 설정 난이도 | 쉬움 (그냥 로그인해서 대화) | 어려움 (코드를 짜야 하고, 계속 돌아가게 할 서버 필요) |
| 누가 할 수 있나 | 팀원 전체 | 어느 정도 컴퓨터를 다룰 줄 아는 팀원 (지금은 둘 다 해당) |
| 지금은 뭐가 맞나 | ✅ 이걸로 충분해요 | 나중에 "정해진 시간마다 자동으로 반복 실행"이 꼭 필요해지면 |

지금처럼 클로드 코드로 팀장 AI를 운영하는 것 자체가 이미 API 기반 AI를 쓰는 것과 비슷해요. 직접 코드를 짜서 API를 부르는 건, 팀원은 몰라도 되고 나중에 완전 자동화가 필요할 때 넘어가면 돼요.

| 상품 추천 AI | 상품 목록 + 주문(order) 이력 — 뭘 같이 사는지 패턴 확인 |
| 인기상품 발굴 AI | 판매 이력(선택) — 외부 트렌드가 메인이라 카페24 데이터는 교차 검증용 |
| SNS 홍보 AI | 상품 이미지·정보 읽기 — 콘텐츠 소재로 사용 |
| 성과 분석 AI | 주문(order) 데이터, 매출 통계 |

*(출처: [카페24 개발자센터](https://developers.cafe24.com/), [Basic Development Guide](https://developer.cafe24.com/docs/guide/basic_development_guide.html))*
## 14. 놓친 부분 체크리스트 (추가로 필요한 것 3가지)
1. **카페24 Open API 연동 계획** — 구체적인 등록 절차와 에이전트별 필요 데이터는 13번 섹션에 정리함.
2. **쇼핑몰 운영에 필요한 기본 법적 요소** — ✅ 확인 완료(2026-09-25): 신규 쇼핑몰은 기존 잼뮤직과 **같은 사업자로 운영**한다. 통신판매업 신고·PG(결제대행) 연동은 새로 할 필요 없이 기존 것을 그대로 쓴다.
3. **성과분석 AI가 볼 구체적 KPI 정의** — 아래 표로 구체화함.
### 핵심 공식: 매출 = 방문자 × 객단가 × 구매전환율
이 3가지 숫자만 잡으면 쇼핑몰 성과의 대부분을 설명할 수 있다 (출처: 이커머스 업계 일반론).

| KPI | 계산식 | 의미 | 담당(태그) AI |
|---|---|---|---|
| 구매전환율(CVR) | 구매건수 ÷ 방문(세션)수 × 100 | 방문자 중 몇 %가 실제로 구매하는지 (일반 평균 1~2%, 상위권도 3% 수준) | 상품 추천 AI, 인기상품 발굴 AI |
| 객단가(AOV) | 매출 ÷ 구매건수 | 한 번 살 때 평균 결제 금액 | 상품 추천 AI (교차판매로 올림) |
| 재구매율 | 재구매 고객수 ÷ 전체 구매 고객수 × 100 | 기존 고객이 다시 사는 비율, 로얄티 지표 | SNS 홍보 AI, 상품 추천 AI |
| 유입수 | 방문자·세션수 | SNS·검색을 통해 사이트로 들어온 사람 수 | 검색최적화(SEO) AI, SNS 홍보 AI |

**에이전트-KPI 연결**: SEO·SNS AI는 "유입을 늘리는" 역할, 상품추천 AI는 "객단가·전환율을 올리는" 역할, 인기상품발굴 AI는 "잘 팔릴 상품을 미리 고르는" 역할로 연결된다. 성과분석 AI 담당(팀원 A)이 이 4가지 수치를 매주/매월 모아서 보고하고, 6번 섹션 "리뉴얼 사이클"을 이 숫자를 근거로 돌린다.
*(출처: 이커머스 업계 일반 지표 정의, 국내 이커머스 평균 전환율 보도 기사 기준)*
## 15. 운영 중 에러 자동 수정 기능
카페24 API 연동, 자동화 스크립트, 웹사이트 운영 중에 에러가 나면, 사람이 일일이 원인을 찾지 않아도 클로드가 먼저 확인하고 고쳐주는 기능이에요.
### 어떻게 동작하나
1. 자동화 스크립트나 카페24 연동에서 에러가 발생 (예: 13번 섹션의 access_token 만료, API 호출 실패 등)
2. 클로드(오케스트레이터)가 에러 메시지를 읽고 원인을 분석
3. **단순한 문제**(토큰 만료, 일시적 네트워크 오류, 입력 형식 오류 등)면 클로드가 스스로 원인을 고치고 다시 실행
4. **판단이 필요한 문제**(아래 "사람이 반드시 봐야 하는 것" 참고)는 자동으로 고치지 않고, 무슨 문제인지 설명과 함께 바로 단톡방에 알림
5. 무슨 에러가 있었고 어떻게 처리했는지는 전부 기록해서 남김 (12번 섹션에서 차용한 "감사로그" 개념과 동일한 방식)
### ⚠️ 절대 자동으로 고치면 안 되는 것 (사람 승인 필수)
- **결제·금액과 관련된 에러** (환불, 가격 오류, 정산 등)
- **고객 개인정보를 바꾸는 작업** (연락처, 주소, 주문내역 수정 등)
- **실제 상품 가격·재고를 바꾸는 작업**
- 클로드가 원인을 확실히 모르는 애매한 에러
이런 건 클로드가 "이런 문제가 있는데 어떻게 할까요?"라고 먼저 물어보고, 사람이 승인한 뒤에만 처리해요. (11번 섹션에서 확인한 개인정보 관련 원칙과 같은 이유예요.)
### 지금 당장(A안, 무료) vs 완전 자동(B안)

|   | A. 지금 당장 (사람이 먼저 발견) | B. 완전 자동 (정기 점검) |
|---|---|---|
| 방법 | 에러 메시지를 보면 단톡방에 붙여넣고 클로드에게 "이거 고쳐줘"라고 요청 | 정해진 시간마다(예: 매시간) 클로드가 알아서 로그를 확인하고 문제를 찾아 고침 |
| 비용 | $0 (지금 쓰는 Pro로 충분) | 12번 섹션과 같은 예약 실행 인프라 필요 (추가 비용은 거의 없지만, 실시간 감지는 아님) |
| 반응 속도 | 사람이 알아챌 때까지 대기 | 정해진 주기마다 자동 확인 (실시간은 아님) |
| 지금 추천 | ✅ 이걸로 시작 | 자동화 규모가 커지고 에러가 잦아지면 그때 전환 |

**결론**: 지금은 A안으로 시작해요 — 팀원이 카페24 관리자 화면이나 자동화 스크립트에서 에러를 보면, 그 메시지를 그대로 클로드에게 붙여넣어 주면 돼요. 별도 설정 없이 바로 쓸 수 있어요. 나중에 자동화 범위가 넓어지면, 12번 섹션의 매주 스카우팅처럼 "매시간 에러 로그 확인" Routine을 추가로 만드는 방식(B안)으로 넘어가면 됩니다.
## 16. 네이버 최저가 모니터링 (가격 경쟁력 확인)
우리 상품이 네이버쇼핑 최저가 대비 경쟁력 있는지 확인하는 기능이에요.
### ⚠️ 브라우저 자동화로 우회하는 방식은 권장하지 않음 (2026-09-25 검토)
네이버는 로봇(자동 접속)을 의도적으로 차단하고 있어요. 이걸 브라우저 자동화나 IP를 바꿔가며 우회하면:
- 네이버 **이용약관 위반**
- 대법원 판례상 대량 크롤링은 **부정경쟁방지법 위반(업무방해)**으로 다뤄진 사례 있음
- 들키면 계정·IP가 통째로 차단될 위험
- 라즈베리파이로 IP를 바꿔도 결국 또 막힐 가능성 높음
**이걸 우회할 필요가 아예 없어요** — 네이버가 이 데이터를 공식적으로 무료 제공하고 있기 때문이에요.
### ✅ 대안: 네이버 공식 "쇼핑 검색 API" (무료)
1. [네이버 개발자센터](https://developers.naver.com)에 네이버 아이디로 로그인
2. Application(애플리케이션) 등록 — 사용할 API로 "검색"(쇼핑) 선택
3. Client ID / Client Secret 발급 (무료)
4. `GET /v1/naver/shop/search`에 상품 키워드를 넣어 호출하면 아래 데이터를 공식적으로 받음:

| 항목 | 내용 |
|---|---|
| lprice / hprice | 최저가 / 최고가 (원) |
| mallName | 그 가격에 파는 쇼핑몰 이름 |
| title, link, image | 상품명, 링크, 이미지 |
| productId, brand, category | 상품 식별 정보 |

**미검증(확인 필요)**: 정확한 일일 호출 한도와 유료 전환 조건은 개발자센터에서 재확인 필요.
### 라즈베리파이 활용법 (아이디어는 살리되 목적 변경)
라즈베리파이를 "24시간 켜둔 자동화 서버"로 쓰는 건 좋은 아이디어예요 — 다만 **봇 차단 우회용이 아니라 공식 API를 정기 호출하는 용도**로 씁니다. 13번 섹션의 카페24 API 자동화와 똑같은 패턴이에요:
```javascript
라즈베리파이 (정해진 시간마다 실행)
   → 네이버 쇼핑 검색 API 공식 호출 (우리 상품명으로 검색)
   → lprice·mallName 등 결과 받음
   → 구글시트/Notion으로 결과 전송
   → 우리 카페24 가격과 비교해서 경쟁력 확인
```
### 담당 및 연결
- **담당**: 상품 추천 AI(팀원 A) — 가격 경쟁력도 결국 "무엇을 어떻게 팔지"의 일부라서 같은 담당이 자연스러움
- **연결**: 13번 섹션의 카페24 Open API(우리 상품 가격)와 이 네이버 API(경쟁사 최저가)를 같이 봐야 진짜 비교가 됨
- **자동화 구현**: 15번 섹션 원칙과 동일 — 클로드(AI)가 API 호출 스크립트를 구현하고, 팀원은 결과가 맞는지 테스트만 하면 됨
*(출처: [네이버 개발자센터 오픈API 가이드](https://developers.naver.com/docs/common/openapiguide/#/productguide/search), 국내 크롤링 관련 법적 검토 자료)*
## 17. 스킬·에이전트 성과 평가 및 자동 업그레이드 시스템
**목적**: 각 AI 역할(스킬)이 실제로 잘하고 있는지 기준을 미리 정해두고, 기준 미달이면 그 설명서를 고쳐서 다시 기준을 넘기게 만드는 시스템이에요. Claude 진영에서는 이걸 공식적으로 "평가(eval) + 고도화(hillclimb)"라고 불러요 (5번 섹션 원칙 #4 "결과를 보고 계속 개선하기"를 실제로 돌리는 방법).
### 어떻게 동작하나
1. 각 AI 역할마다 "합격 기준"을 미리 구체적으로 정해둠
2. 결과물이 나올 때마다 그 기준을 통과했는지 확인
3. 기준 미달이면 → 왜 실패했는지 원인 분석 → 그 설명서(Skill) 파일의 해당 부분을 고침 → 다시 확인
4. 이 사이클을 반복하면서 설명서가 점점 좋아짐
### 담당 AI별 합격 기준 예시

| AI | 합격 기준 예시 | 어떻게 확인 |
|---|---|---|
| SEO AI | 상품명에 모델명+기능 포함, 메타설명 150자 이내, GEO 필수 피드 항목(3번 섹션) 다 채움 | 결과물 직접 확인 (체크리스트) |
| 인기상품 발굴 AI | 추천한 상품이 실제로 네이버 검색량·유튜브 언급량 기준 상위인지 | 16번 섹션 API로 사후 검증 |
| 상품 추천 AI | 교차판매 클릭률, 객단가(AOV) 상승 여부 | 14번 섹션 KPI로 측정 |
| SNS 홍보 AI | 게시물 도달·좋아요 수, 브랜드 톤 일치 여부 | 팀원 검수 + SNS 자체 통계 |
| 성과 분석 AI | 보고서에 14번 섹션 4대 지표(CVR·AOV·재구매율·유입수)가 다 들어갔는지, 숫자가 실제 카페24 데이터와 일치하는지 | 팀원 대조 확인 |

### A안(지금 규모, 무료·수동) vs B안(나중에, 공식 자동화 기능)

|   | A. 사람이 체크 (지금 방식) | B. 클로드 공식 자동 평가+고도화 |
|---|---|---|
| 방법 | 위 체크리스트를 팀원이 직접 훑어보고, 기준 미달 항목을 클로드에게 알려주면 클로드가 원인 분석 후 설명서 수정 | 미리 만들어둔 여러 테스트 케이스(평가셋)를 클로드가 자동으로 돌리고 점수를 매겨서, 기준을 넘을 때까지 스스로 설명서를 반복 개선 |
| 비용 | $0 (지금 쓰는 Pro로 충분) | 실제 API 비용 발생 — 평가를 한 번 돌릴 때마다 진짜 돈이 나감 |
| 필요한 것 | 팀원이 체크리스트 보고 판단만 하면 됨 | API 키 + "무엇을 평가할지" 테스트 케이스를 미리 만들어둬야 함 |
| 지금 뭐가 맞나 | ✅ 이걸로 시작 | 나중에 역할별 결과물이 많이 쌓이고 "숫자로 품질을 관리하고 싶다" 싶을 때 |

**⚠️ 주의**: B안(자동 평가+고도화)은 실행할 때마다 실제 API 비용이 발생하는 기능이라, 함부로 반복 실행시키면 안 되고 사람이 예산과 실행 여부를 먼저 정하고 승인해야 해요 (15번 섹션의 "사람 승인 필수" 원칙과 같은 이유).
**⚠️ 확인(2026-09-25): 지금 쓰는 Claude Pro 구독으로는 이 B안을 쓸 수 없어요.** 이건 claude.ai 구독(Pro·Max·Team)과는 완전히 별개인 "Anthropic Console"이라는 곳에서 별도 API 키를 만들고, 쓴 만큼만 신용카드로 결제하는 방식이에요 (구독료와 무관한 완전히 다른 결제 체계). 다만, 그 공식 기능 없이도 **지금 쓰는 클로드 코드(구독) 안에서 대화로 "이 5개 결과물을 기준에 맞춰 체크하고 설명서 수정해줘"라고 반복해서 요청하면**, 점수화된 자동화는 아니지만 "평가→개선"의 효과는 비슷하게 낼 수 있고, 이건 지금 구독만으로도 가능해요 (바로 위 A안이 이 방식이에요).
**15번 섹션(에러 자동 수정)과의 차이**: 15번 섹션은 "고장(에러)"을 고치는 거고, 17번 섹션은 "고장은 아닌데 잘 못하는 것(품질)"을 고치는 거예요 — 둘 다 "문제를 발견하면 사람 없이 때로는 고치고, 때로는 사람 승인을 받는다"는 같은 구조예요.

- 도구: **"스마트스토어 쿠팡 분석 - SMART DATA 스마트데이터"** 크롬 확장 프로그램 — 네이버 스마트스토어·쿠팡 상품 리뷰 추출, 판매량 분석 등을 제공
- 사용 방식: 10번 섹션의 옵시디언 흐름과 같은 패턴 — **팀원이 직접 브라우저에서 확장 프로그램으로 경쟁사 상품 페이지의 리뷰를 수집**한 뒤, 그 내용을 클로드에게 붙여넣으면 클로드가 "자주 언급되는 불만 키워드"를 뽑아서 정리
- 16번 섹션(공식 API로 최저가 확인)과 짝을 이루는 "경쟁사 분석"의 또 다른 축 — 16번은 가격, 이번 건은 품질·만족도
### 담당
상품 추천 AI(팀원 A) — 16번 섹션과 같은 이유(경쟁사 분석은 "무엇을 어떻게 팔지"의 일부)
### ⚠️ 예상되는 문제점 (규칙 5)
1. **자동화 아님**: 이 확장 프로그램은 사람이 직접 브라우저를 열어서 눌러야 동작 — 16번 섹션처럼 API로 완전 자동화는 안 됨 (지금은 A안 성격: 사람이 수집 → 클로드가 분석)
2. **플랫폼 이용약관 확인 필요**: 이 확장프로그램은 서드파티 도구라 스마트스토어·쿠팡이 공식으로 허용하는지와는 별개일 수 있음 — 16번 섹션에서 네이버 크롤링을 자동화 봇으로 하면 안 된다고 결론 낸 것과 같은 맥락에서, **대량·반복 수집(예: 수백 개 상품 자동 순회)은 피하고, 사람이 필요할 때 개별적으로 확인하는 용도로 한정**하는 게 안전
3. **경쟁사 리뷰 원문을 그대로 베끼거나 노출하면 안 됨**: 분석 결과(불만 키워드)만 우리 상품 기획에 참고하고, 경쟁사 리뷰 원문을 우리 콘텐츠에 그대로 쓰면 안 됨
